Abstract
We will explore a hierarchical data structure called a Cover Tree and show how it can be
used to solve the fully dynamic k-clustering problem. We will explore the two different
representations of the internal structure of the tree, and show how all the algorithms that
are used to manipulate the data structure itself are used. We shall prove that a single
Cover Tree can be used as an 8-approximation for the fully dynamic k-clustering problem,
and show that insertions can be done in time O(c6log(n)) while removals can be done in
O(c12log(n)2). We will also show that it is possible to bring the time down to O(c6log(n))
for removals. The Cover Tree will also support three queries: what are the cluster centers,
is p a center and what center is p assigned to, all in O(c6log(n)k) time. Everything will be
done using just O(n) space. Then we will develop the Cover Forest data structure. We will
describe the Cover Forest and its algorithms and show that it can be used to solve the fully
dynamic k-clustering problem with an approximation of (2 + ϵ), while only multiplying
the base run times and space usage of a single Cover Tree by a factor (1+ϵ)(ln(2)−ln(ϵ))

Introduction
It is commonly known that the amount of data generated and processed increases every
year. As such, many areas of society process a greater amount of data each year, be that in
the scientific community, marketing or governments. Due to the increase in data quantity,
researches are looking into more eﬀicient methods of doing data analysis. One commonly
used tool in data analysis is clustering. The main premise behind clustering is to gather
points of data that are ”alike” into one cluster, and gather points that are not into other
clusters. There are many applications where this kind of clustering is useful. Notably
in unsupervised machine learning in the clustering, classification or image segmentation
setting. Or in a database oriented setting where clustering can be used for fraud detection
and customer segmentation.
The clustering problem can be defined in many ways. Using different distance measures
like the euclidean, Manhattan or Hamming distances. This can then be applied to dif-
ferent clustering schemes, e.g. partition clustering like the k-means clustering, sequential
clustering or hierarchical clustering.
In this paper we shall look at the arguably most simple type of clustering, the k-center
clustering using a euclidean distance measure.
The goal of k-center clustering is simple. Given a set of n points in S, create k ≤n
cluster centers such that for every center c and every point in p ∈S the distance d(c, p)
is minimised, while the distance from any point p ∈S to any cluster center c is at most
this distance. [KH79] showed that this problem is NP-hard. Hence the research have been
on developing approximation algorithms to solve the problem. Given some α ≥1, an α
approximation is a solution to the k-center problem that is at most α times worse than
the optimal solution. Algorithms like the Bottle Neck algorithm have been developed and
solve the static k-center with an approximation of 2 [Gon85].
The problem with the static approach is of course that it is static. But in many situations
it might be favourable if the dataset could evolve. E.g. adding a point to a map, adding
a row to a database because of a new tweet or credit card transaction somebody made.
In situations where we wish to modify the points we made our clustering on, we have to
re-cluster the whole data set when we have added or removed a point. This is obviously
disadvantageous, as it is impossible to keep any of the previously done work.
This is the Dynamic k-clustering problem, maintaining k clusters of minimum radii under
insertion, deletions or both. Some dynamic k-clustering algorithms only support insertions
and are described as incremental.
Other support both insertion and deletion and are
described as fully dynamic, and is the exact setting that we shall explore in this paper.
As we shall see, many solutions in the next section have some dependency on k for their
running time. For applications where k is relatively small this might not be a problem,
but in instances where one wish to use a myriad of clusters, this dependency might be
unfavourable, e.g. with servers on the internet. This lead to the initial developments in
[Gor+20] and now to the Cover Forest data structure.

[Gor+20] cover the k-center problem extensively and is the inspiration for the Cover
Forest data structure we shall see later. They develop a set of hierarchical data structures
called Navigating nets, that were introduced by [KL04] that initially described Nearest
Neighbour Search (NNS), Approximate Nearest Neighbour Search (ANNS) and Range
Query algorithms and how the structure behave under insertion and removals of points.
The Navigating Net itself is a hierarchical structure, consisting of many layers of r-nets,
where each r-net is designated an integer i ∈Z that describes its position or layer in
the hierarchy. Each r-net then satisfies two invariants, the covering and the separation
invariant. Given a set of points p ∈S and an r-net Ri, we have that for each point r ∈Ri
it must be that d(r, p) ≤αi for some α > 1, and also that for any two points r, r′ ∈Ri
we have that d(r, r′) > αi. These two rules were the covering and separation invariants
respectively.
A Navigating Net is then the set of all r-nets {R∞, ..., R−∞} where two
special sets are added to each level, these sets refer from the current level i to i + 1 and
i −1, but we will not cover how they do so.
[AL06] extended the work of [KL04] to create the Cover Tree data structure, this is also
a hierarchical structure that satisfy the same invariants and some extra. We shall later
delve into exactly how the Cover Tree works, but suﬀice to say for now that [AL06] like
[KL04] introduced their data structure with descriptions of NNS, ANNS, insertions and
removals. Shortly after the publication of [AL06], [Kol06] presented a review of [KL04]
and [AL06], where they rectify a small error in the original insert algorithm by [AL06].

The problem of clustering data into clusters of minimal radii is notoriously diﬀicult.
[Gon85] showed that achieving any approximation ratio of 2 −ϵ is NP-Complete, hence
we cannot hope for any better than a 2-approximation unless P = NP. If we do not wish
to compute every possible clustering by brute force.
1.2
Applications
The task of clustering data into meaningful clusters is done in much data analysis. In
recent years especially in machine learning, where one might have a dataset consisting of
many points of undefined dimension. When a new point comes along the question is now,
which cluster does it belong to. This idea can be used for tasks like segmenting customers,
the goal of this is to segment the customer data into clusters. Consider for example, that
young people send many text messages but talk little on the phone, and that older people
send few text messages but talk more on the phone. We might cluster these two groups
and offer discounts on text messages to the former group and discounts on talk time for
the latter group.
Another area of use is in fraud detection. One could imagine that a bank could cluster
their transactions in some way. Now if a new point falls outside the clusters it may be a
sign of a fraudulent transaction.
Finally we have the problem of placing stores or distribution centers. Imagine that you
want to place stores in the towns of some country, such that the distance to your store is
minimised for all towns. The catch is that you cannot place stores in every city, so you
must chose what towns to place them in. This problem is a good analogue for the two
dimensional k-center problem.

Background
In this section we shall quickly review some basic definitions that will be essential to the
remainder of this paper. We shall define the metric space, the notation of balls on that
space, and the expansion constant and doubling dimension on that space.
2.1
Metrics
A metric space is defined as a non empty set of points M and a distance function d
usually combined to form (M, d). The distance function d take as input two points in M
and maps them to some real number R. Additionally, the distance function must for all
points x, y, z ∈M satisfy the following four invariants.
Reflexivity
d(x, x) = 0
(2.1)
Positivity
d(x, y) > 0 ⇐⇒x ̸= y
(2.2)
Symmetry
d(x, y) = d(y, x)
(2.3)
Triangle inequality
d(x, y) + d(y, z) ≤d(x, z)
(2.4)
Definition 2.1.1. The distance from any point p to any set S ⊂M is defined as
d(p, S) = minq∈Sd(p, q)
(2.5)
2.2
Open and closed balls
The notation of a ball vary from paper to paper, but we shall use B(p, r). A ball B(p, r)
is defined as a set of points q ∈(M, d), that are within some distance r of the center point
p ∈M. Formally:
Definition 2.2.1. An open ball B(p, r) is defined as Bo(p, r) = {q ∈M : d(p, q) < r}
Definition 2.2.2. A closed ball B(p, r) is defined as Bc(p, r) = {q ∈M : d(p, q) ≤r}
We will drop the subscript when it is clear from the context if it is an open or closed ball.

2.3
The expansion constant and doubling dimension
The notion of a growth rate for metrics have been defined in many papers. In this paper
we shall focus on two variants, the doubling dimension as introduced in [KL04] and used
in [Gor+20]. And the expansion constant as introduced in [AL06] and used in[Kol06].
The doubling dimension deal with sets and of some radii, and the expansion constant with
the size of balls of some radii. The radii of a set (or ball) is defined on a subset S ⊆M,
where the radii of S is max(d(p, q) : p, q ∈S). As seen in section 2.2, we can also define a
ball to have a predefined radii.
Definition 2.3.1. The doubling dimension of a metric space is the smallest value κ
(Kappa) such that every set B(p, r) ∈(M, d) can be covered by 2κ sets of half the radii
Definition 2.3.2. The expansion constant of a metric space is the smallest value c ≥2
such that for every point p ∈M and radii r > 0 we have that |B(p, r)| ≤c|B(p, r/2)|
For the sake of example, let us look at the first two dimensions. It is easy to see that a
line of length 2 can be covered by 2 lines of length 1, yielding c = 2 for the first dimension
(see fig. 2.1c). Given that the area of a circle is A = πr2 we see that π2r2/πr2 = c = 4. In
general, if the points in the metric are arranged uniformly on some d dimensional surface,
then c ∼2d ([AL06]). Note that we can not cover the ball of large radii with c balls of
smaller radii, the expansion constant only state that the size of the balls have this specific
relationship. A covering of a ball of radii 2r using c balls of size r is not possible, as some
overlap is required to cover the bigger ball. But no overlap is allowed by the lower bound
for c given definition 2.3.2. An attempt of a 4 cover can be seen in fig. 2.1b, where the
part not covered has the same size as the size of the overlap.
It is non-trivial to show a bound for the doubling dimension κ, showing how to find this
value for metric spaces is beyond the scope of this paper, but the interested reader is
referred to [LG05]. Do note that for two dimensions this can be done using 7 balls, as
shown in fig. 2.1a.

3
The Cover Tree
The Cover tree data structure were introduced by [AL06] and is a refined model of the
Navigating net as introduced by [KL04]. The Cover tree define a tree structure much like
the Navigating nets does. The Cover tree has layers just like a Navigating net, and uses the
same scales r = 2i for the balls on each level i. However the Cover tree is a conceptually
simpler data structure as it removes many of the links that are present in the Navigating
net. The Cover tree data structure were first introduced for fast nearest neighbour searches
on metric spaces, where insertions and deletions are required. [Gor+20] found that the
Cover tree could immediately be used to solve the k-center problem with good bounds
and an 8-approximation factor. They further extended it with their techniques from the
Navigating net to obtain a (2 + ϵ)-approximation factor for the Cover tree.
[Gor+20]
mainly focus on the Navigating net for their theoretical analysis, and lean on the findings
of [AL06] for the experimental section.
Many papers that use the Cover tree do not
dive in deep with the inner workings of the data structure.
And [AL06] describe the
Cover tree in a highly compressed manner. For these reasons we shall fully define and
describe the Cover tree and its algorithms with the intent of solving the k-center problem.
Before defining the Cover tree, it is important to clarify some naming conventions. The
Cover tree has two representations, in [AL06] these are called the Implicit and Explicit
representations. Henceforth we shall refer to these two representations as the Full and
Partial representations, as the original naming conventions caused some confusion in the
preliminary work of this paper.
3.1
The data structure
The cover tree is a tree structure on some set of points S drawn from M. Each level in
the tree is associated with some index i, and Ci constitutes all the nodes in a specific level
i. The tree is usually depicted in an upside down manner. The root at the top in level ∞
and the leaves at the bottom in level −∞. Each node N in the tree is associated with a
specific point p ∈S, the tree can have multiple nodes (N, N′) associated with the same
point p. However, we require that if N ∈Ci, then N′ ∈Cj, such that j ̸= i. We also
require the tree to satisfy the following invariants for each level i. If all invariants are
satisfied, then each Ci is a cover of Ci−1.
3.1.1
Properties
The cover tree proposed by [AL06] maintain the following three invariants:
(Nesting) Ci ⊂Ci−1
(Covering) ∀q ∈Ci−1, ∃p ∈Ci : d(p, q) < 2i
(Separation) ∀p, q ∈Ci, d(p, q) > 2i
• The nesting invariant state that Ci is a subset of Ci−1, this implies that, if a node
exist in level i, then it exists in all levels j ≤i.
• The covering invariant state that for all nodes q in level i −1 there exists a node p
in level i such that the distance between all q and p is less that 2i. If we think of a
single p ∈Ci, then all q ∈Ci−1 within that distance are children of p the parent.
• The separation invariant state that all distinct nodes in Ci must be more than 2i
apart. This, combined with the covering invariant ensure that for a parent p and its
children q it holds that 2i−1 < d(p, q) < 2i.

The Covering and Separation invariant gap
We will now get back to the gap between the covering and separation invariant. Firstly
we shall see why there is a gap, and at what distances it exists. Then we shall explore the
possible solutions to this problem, and present the solution we shall use moving forward.
Finally we will see that this solution indeed removes the gap and allows all three invariants
to be satisfied at the same time.
Lemma 4.1.1. The covering invariant and the separation invariant proposed by [AL06]
cannot be satisfied at the same time, for some two points {p, q} and their distance d(p, q).
Proof. We consider our two points {p, q} and wish to find the sets Ci they each must be
located in. We assume that d(p, q) = 2j. The covering invariant is used for all the levels
where either p or q can cover one another, that is, they are close enough. Where the
separation invariant is used for all levels where p and q are far enough from each other.
Let us first find all the cover sets Ci where p or q can cover one another. W.o.l.g. assume
that q need to cover p. In order for q in Ci to cover p in Ci−1, their distance must be
d(p, q) < 2i. Their distance is d(p, q) = 2j so if q is in Cj then p cannot be in Cj−1 as
d(p, q) = 2j ̸< 2j. If q ∈Ci for all i = {∞... −∞}, then it can cover p if p ∈Ci for all
i = {∞...j}.
Now, let us find all the Ci where p and q are far enough away from each other. As their
10
Dynamic k-clustering
==PAGE:19==
distance d(p, q) = 2j ̸> 2j, they cannot both exist in Cj, they can only both exist in Ci
for all i = {j −1... −∞}.
To satisfy the covering invariant, they must both be in Ci for all i = {∞...j + 1}. And to
satisfy the separation invariant they must both be placed in Ci for all i = {j −1... −∞}.
As such there exists no set Ci where we can place p and q to satisfy both the covering and
separation invariant.
If we allow distances between two points to be some power of two, there are times where
we cannot satisfy all invariants for that tree. There are two solutions. Either assume that
the distance between two points can never be some power of two. Or change the invariants
such that there is no gap between them. [Kol06] changed the covering invariant to use a
distance d(p, q) ≤2i, but did not remark on why this change were made. Alternatively,
one could have changed the separation invariant to use a distance d(p, q) ≥2i, but for
the rest of the paper we shall assume the invariants of [Kol06]. The new invariants of the
cover tree are then as follows.
(Nesting) Ci ⊂Ci−1
(4.5)
(Covering) ∀q ∈Ci−1, ∃p ∈Ci : d(p, q) ≤2i
(4.6)
(Separation) ∀p, q ∈Ci, d(p, q) > 2i
(4.7)
Theorem 4.1.2. For any two points p and q with any distance d(p, q), it is possible to
satisfy the Nesting eq. (4.5), Covering eq. (4.6) and Separation eq. (4.7) invariants.
Proof. Let us consider this in three cases: d(p, q) = 2j, d(p, q) = 2j −δ and d(p, q) = 2j +ϵ
where 0 < δ < 2j−1 and 0 < ϵ < 2j.
Assuming that d(p, q) = 2j, if q ∈Ci for all i = {∞...−∞}, then it can cover p if p ∈Ci for
all i = {∞...j −1} satisfying the covering invariant for those Ci. To satisfy the separation
invariant, as the value 2i is the largest at i = j −1 they can both exist in all Ci for
i = {j −1... −∞} without violating the separation invariant. Additionally, as they are
in all those levels the nesting invariant is also satisfied, p cover itself for each set Ci for
i = {j −1... −∞} and q cover itself for each set Ci for i = {∞... −∞}, satisfying the
covering invariant.
Assuming that d(p, q) = 2j −δ where 0 < δ < 2j−1.
Hence, we have that 2j−1 <
d(p, q) < 2j. We can satisfy the covering, separation and nesting invariants using the
same arguments and sets as when d(p, q) = 2j
Assuming that d(p, q) = 2j +ϵ where 0 < ϵ < 2j. Hence, we have that 2j < d(p, q) < 2j+1.
If q ∈Ci for all i = {∞... −∞}, then it can cover p if p ∈Ci for all i = {∞...j} satisfying
the covering invariant for those Ci. To satisfy the separation invariant, we have that 2i
is the largest at i = j they can both exist in all Ci for i = {j... −∞} without violating
the separation invariant. The covering invariant is satisfied by the same approach as with
d(p, q) = 2j.
Thus, there are no gaps and no value that can be assigned to the distance d(p, q) between
any two points p and q where we cannot for each point, place them in some sets Ci such
that all three invariants are satisfied.

from p. Then as input to the next recursive call we use (p, Qi−1, i −1).

The goal of the algorithm, is that given some Cover tree T and a point p ∈T, the remove
algorithm must create a new tree such that T = {T \ p}. As always, the new tree T must
satisfy the three invariants, if not, then the T is not a valid Cover tree.
Removing a point p from the tree is inherently more diﬀicult than inserting one. The
reason for this is that when removing a point, then we have to remove several nodes in
T. This in and of itself is not demanding, but for each node we remove, there may be
sub-trees that need to be replaced and assigned to new parents in order to reconnect the
tree. This is of course possible, but it requires a bit of tact.
The removal algorithm, like the insert, is a recursive algorithm and run in two main
phases, the last of which has one sub-phase.
The recursive steps take as input (p,
{Qi, Qi+1, ..., Q∞}, i), where p is the point we want to remove, {Qi, Qi+1, ..., Q∞} are
cover sets and i is the current level.
Just like the insert algorithm we initialise it with Q∞= C∞as the root.
Then, in
the first phase it generates the set {Qi−1, Qi, ..., Q∞} and recursively calls itself with (p,
{Qi−1, Qi, ..., Q∞}, i −1) as input. For each recursive call from Q∞to Q−∞it generates
all Qi.
Phase 1 - Going down
The first phase of remove recurses down the tree constructing
cover sets. It is easiest to consider the construction of a single Qi−1 on level i, so let us
construct one such set. Firstly we construct the set Q, this is an intermediate step and Q
is not carried down the recursion stack like the Qi’s. Q on level i is constructed such that it
contains all the children of the previous cover set Qi. Note that Qi is constructed just like
our current Qi−1, just one step up the recursive chain on level i+1. After having gathered
all children of Qi into Q we need to include only those that are ”close” to the point p when
constructing Qi−1. All nodes that are not ”close”, can not lead us to p. Nodes close to
p are nodes associated with the points q such that d(p, q) ≤2i. This ensures that points
in the next cover set (Qi−1), do cover p, as such they can lead to the nodes associated
with p. After having constructed Qi−1, we construct the input to the next recursive call
as {Qi−1} ∪{Qi, Qi+1, ..., Q∞}. Where the right side is of course the input given to this
recursive call from the previous call. Therefore for all i = {∞, ..., −∞}, we propagate all
the cover set Qi down the recursive stack. The recursion stops when p is always implicit,
here we need to make a definition as this implicitness is not clearly stated in [AL06].
Definition 4.2.3. The level j at which p is implicit for all levels i = {j... −∞}, is the
first level j where p never branch for all levels below. That is, if p branches for the last
time on level j + 1, then p is implicit for all levels i = {j... −∞}.
When reaching the level at which p is implicit, we have constructed all relevant cover sets
{Q−∞, ..., Q∞}. Now, the second phase can begin.
Phase 2 - Going up
The second phase deal with going up the recursive stack, it is
here where we actually remove the nodes and reassign the children. The reassignment of
the children is a sub-phase within this phase.
Having generated every relevant Qi on the way down, we now start climbing the recursive
ladder. We shall again consider that we have done some amount of steps and now reach
the call with input (p, {Qi, Qi+1, ..., Q∞}, i), where we also have generated Q and Qi−1.
If we stay true to step 4 described by [AL06] we test if d(p, Q) = 0, this is analogous to
testing if p ∈Q and we shall use this going forward. If p /∈Q, then the recursive call
just continue up with no further changes at this level. If however p ∈Q, then we known

Full representation k-clustering
To round of the full representation chapter, let us bring it back to the main point. How
do we use the cover tree to create a clustering. Note that we will cover how good this

Finding a k-clustering is quite simple. Just like with insert and remove, start with Q∞=

and then start expanding the children of Qi−1 to Q using Q = {Children(q) : q ∈Qi−1}.
If at any point |Q| = k, then return Q as the answer. If |Q| > k, then create a temporary
holding set R and set R = Qi, at this point |R| < k. So arbitrarily pick nodes from Q \ Qi
and add them to R, do this until |R| = k. Now return R as the answer. We are sure to
have enough nodes as |Q| > k and |Q| > |Qi|.

5
Partial representation
In the Full representation we had some creature comforts. We had a single universal root
in Q∞= C∞and universal leaves in Q−∞= S. We had the notion of levels i and an
easily accessible cover set Ci on a single level i. In the partial representation we have fewer
nodes, no levels and as such, no true cover sets Ci. Hence we have no easy relationship
to the tree invariants. The goal of the partial representation is to remove all unnecessary
nodes, but still ensure that all of the functionality of the full representation cover tree can
be preserved, that is all invariants are still true, and its run times are the same. We will
show that this can be done but with a smaller data structure size.
As we no longer have a clear notion of levels as we had in the full representation, we need
to do many thing differently. The structure of the tree has changed and the algorithms
that run on it are different, the skeleton and general premise is the same, but many things
are done differently.
As we shall see later, the partial representation has a linear space bound, and is therefore
more suitable for implementation than the full representation, given that it can do all the
same things and with no drawback on time complexities.

Definition 5.1.4. SelfChild(p) is the child c ∈Ch(p) such that c and p are associated

Definition 5.1.5. The special node ”root” is the acting root node. It is equivalent to the
full representation root in C∞.

5.2.1
The construction of cover sets Q
All algorithms given by [AL06] construct the set Q layer by layer. This is the first situation
where the new algorithms need to be modified to work with the partial representation as
if it were the full one. The construction of Q is an integral part of the algorithms, so we
need to be able to interpret the partial tree in order to construct the correct cover sets Q
for each level. In order to keep the same Q’s in the partial model, we construct Q in the
following way.
Q = {q ∈Qi : i −1 ∈Range(q)} ∪{Children(q) : q ∈Qi, i −1 ∈Range(q)}
(5.1)
Lemma 5.2.1. The constructed Q in eq. (5.1) on level i is analogous to the normal
construction of Q on level i in the full representation.
Proof. The first part keep the nodes in Qi if they are still in the range i −1, that is
analogous to the node having a self child on that branch in the full tree. We union that
with the children of the elements in Qi, but only if they have a range that include i −1,
this ensures we do not include children too early. Imagine a coalesced node on level i, it
may have a child somewhere down the tree say on level j, at this point we can see the
lower node, as it is included in the children of Qi, but we should only include it when
constructing Qj using the nodes in Qj+1. Because we construct Q in this way, we can
work with the Q as if it were constructed from the full representation itself.

Proving the Cover Tree
In this section we shall first prove some preliminary theorems to aid us in the later proofs.
Notice that for all proves regarding the run time of the cover trees, and later the cover
forest, are in expectancy, as we use hash tables for our cover sets, which have O(n) space
usage and O(1) insertion, deletion and query run time in expectancy.
6.1
Approximations, preliminary theorems and lemmas
In the next two sections we shall see a selection of proofs that will prove run time and
correctness of the developed algorithms. Before tackling this we need to prove some facts
about the cover tree as the analysis of proving the algorithms depend on these facts. Notice
that three theorems (theorem 6.1.3, theorem 6.1.5 and theorem 6.1.6) were initially proven
by [AL06] in their lemmas 4.1, 4.2 and 4.3. They are reiterated here for the completeness
of the analysis, and as the covering invariant were changed, some of the inequalities are
also changed. Not greatly, but changes have been made. In addition to this we take care
to explore and explain the reasoning behind the argumentation, and include graphical
representations. This will yield a more detailed analysis that is easier to follow. The goal
of this extra detail is to make it possible for the reader to be convinced by the proofs
without any diﬀiculty or resorting to further material.
Theorem 6.1.1. A single cover tree is an 8-approximation of the k-center problem
Proof. Given a point set S and a Cover tree T on S. To select a k-center clustering we
traverse down the T layer by layer. Each new node encountered is added to the point set
K. This continue so long as |K| < k. Consider two layers |Ci| < k < |Ci−1|, then all
points in Ci are added to K, followed by arbitrary distinct points in Ci−1 until |K| = k.
As |Ci| < k, there is at least one point p ∈Ci that cover at least two points in Ci−1. One
such point may be p itself, but the other is distinct from p. Points in Ci−1 are at least
2i−1 apart, and each ball of size 2i−2 cover at most one point in Ci−1. The optimal cluster
can therefore cover at most k points, but Ci−1 > k. 2i−2 is therefore a lower bound for
the optimal clustering as it cannot cover all points in Ci−1 using a radii smaller than this.
The maximal radii of Ci is at most 2i. Due to the Covering property of T, this radii covers
all points in Ci−1, but not necessarily points in {Ci−2...Ci−∞} as they may be further than
2i away from any point in Ci. Though, as P−∞
i=0 2i = 2i+1, the points in Ci can cover all
their descendent with a radii of 2i+1, therefore covering all of S.
As 2i+1
2i−2 = 8, the solution K on the cover tree T is an 8-approximation k-clustering.
Lemma 6.1.2. The space usage of a single Partial Representation Cover Tree is O(n).
Proof. We assume that every point has at most one parent other than its self parent, as it
is possible for a child to be covered by multiple points in they layer above, hence multiple
points are candidates for parenthood. Notice that each point we either insert or repair
can at most split one other node at one spot. Thus creating a node for itself as a child in
addition to at most one self child of the parent. Hence for each insertion two new nodes
are added, or in the repair case one extra node is added and one is relocated. Thus at
most two new nodes are added when splitting a node due to manipulation of the tree.
Therefore with n points the space usage of a single cover tree is O(n).

Theorem 6.3.5. MergeNode() - algorithm 11 correctly merges a Parent node with its self

Proof. If there is no child, then Parent is a leaf, hence there is nothing to merge. If the

either hence Child were a leaf and merging between Parent and Child is suﬀicient. If

Parent, hence Parent cover the range that the original Parent and Child did, and all
necessary connections are re-established. Notice also that the range High(Parent) do not
change, and Low(Parent) = Low(Child) after the merge, hence neither the covering nor
the separation invariants are violated. And as the new Parent node cover the same as the
old parent and old child, the nesting invariant is also satisfied.
Finally, as we are working on the cover sets Qi we need to update those. We only get
cover sets from {Qi−1, Qi+1, ..., Q∞} where i−1 is the current level that our removal node
were located in. It is fine that we do not update the cover sets Qi−2 or lower, as we
will not revisit those again as we have passed them in the recursion going up. But we
might revisit every cover sets {Qi−1, Qi, ..., Q∞} when we later repair the children of the
removed node. Hence we run ReplaceInQis() to replace all instances of Child with Parent
in {Qi−1, Qi+1, ..., Q∞}.

The Cover Forest
In this section we will create a forest of cover trees, a Cover Forest. This is of course
inspired by the techniques used in [Gor+20] that showed how this forest principal could
be applied for Navigating nets.
Almost all of the work of [Gor+20] were focused on
analysing the Navigating net collection and showing the theoretical bounds of this. As
such their analysis is also based on this navigating net perspective. In this section we
shall take the perspective of the cover forest, where we will first give an introduction to
the cover forest and show how it is constructed. Then we will quickly describe how to
handle this forest of cover trees, which, as it turns out, is not diﬀicult, as most of the
work is done in the individual cover trees. The forest is really just a wrapping and some
management of data. Finally we shall look through the proofs of correctness and run time,
most of this will again just be a short extension of the cover tree correctness and run time.
To end of we will also prove the (2 + ϵ)-approximation of the cover forest, and show how
to compute the clustering and interpret the levels to get a cluster radii.
7.1
The data structure and the algorithms
The idea behind the cover forest is the same as the collection of navigating nets used in
[Gor+20]. We will start by introducing some variables that will be used throughout this
section.
The value α is the base that we raise to some power when evaluating the levels. In the
cover trees we used α = 2 exclusively and created the level radii using 2i, now we will use
αi to create the level radii. Notice that α > 0 as we neither want 0 or negative distances
on the level radii.
The value m is the amount of cover trees that are in the cover forest. It will become
apparent soon how this is calculated and how it interacts with the forest and the approx-

In this section we evaluate the effectiveness and eﬀiciency of the developed algorithms,
that is, the insert, remove and query algorithms. The algorithms described in chapter 5
and chapter 7 are implemented using C# .NET Core 3.1. All executions were done on
Windows 10 Version 20H2 using a Intel(R) Core(TM) i5-4690K CPU @ 4.20GHz with
16GB of system memory.
To get a base case that we can compare to throughout this section, let us first consider
how a single Cover Tree preforms before moving on to testing the Cover Forest. In This
case we can see our single tree as a Cover Forest with just one tree T.
This experiment was conducted on synthetic data. In total we generate 20.000.000 (20M)
points of data, each point has an identifier and two values denoting its position on the
plane. Note that for each point with coordinate values x, we have that ||x||∞= maxi |xi| ≤
10M. During the test we had a sampling rate of 1/50000. That is, for every 50K points
that were inserted into T, we sampled the runtimes at that point count. So we insert
points into T in sets of 50K, note that we do not time this process. When we reach values
of 50K, 100K, 150K, ..., the insertion is temporarily stopped. Now 2K points are randomly
sampled from the points currently in T, then for each of these points we first remove it
from T, then insert it back into T. We time the process of removing and inserting. When
every point have been removed and reinserted we log the current point count, and the
average time it took to remove and reinsert the 2K points.

Discussion
[KL04] introduced the navigating net data structure to find nearest neighbours in metric
spaces quickly, and allowed for points to be inserted and removed.
[AL06] improved
upon this by cutting away all unnecessary connections, they constructed the cover tree
data structure and presented three relatively simple algorithms for insertion, removal and
query. The goal were still to solve the nearest neighbour problem quickly in metric spaces.
[Gor+20] used the navigating net data structure to develop a data structure and algorithms
to solve the k-center problem with a (2+ϵ)-approximation. They then proceed to use this
technique to implement a similar structure using the cover tree structure. The cover tree
structure itself can be implemented in two ways, either as the full representation, or as
the partial representation. Reading through the implementations and documentation of
[Gor+20], [AL06], and other implementations like [Cra] and [Löh]. It is not immediately
clear whether they implement the full or partial representation, as none explicitly state if
they used the one or the other approach, in a place where it would be logical to find such
information. Looking at the code, most evidence point to the use of the full representation
in all the mentioned cases, usually because the implemented node classes use single values
to denote their level, and we believe it is necessary to have at least two to implement
the partial representation. There is also a distinct lack of functions that split and merge
nodes, that we also believe to be necessary to handle the partial representation correctly.
As we saw, the partial representation posed several problems because of the coalesced
nature of the nodes. In the case where nodes are not coalesced we would have a space
bound of O(n · (c2 log(n))), at most n nodes on every one of the O(c2 log(n)) levels. The
partial representation also require much more management of the nodes with merging and
splitting of nodes. This extra computation may be undesirable in situations where speed
is key. In that case it may be more favourable to implement the full representation and
use a factor O(c2 log(n)) more space, which may not be a great increase in some cases.
The cover sets that are generated during execution, constitute a large amount of volatile
data. That is, the cover sets are created for the sole purpose of enabling the manipulation of
the cover tree by other algorithms. They are neither saved or reused after each initialisation
of insert or remove (notice the the query uses three cover sets that are overwritten in turn).
Hence for each initialisation there are O(c2 log(n)) containers that are discarded. Hence the
garbage collection during execution is quite large. Which might be one of the reasons for
the poor performance we saw in the Experimental section. Other factors that can impact
the performance is memory limitations, overhead in container classes, or plainly errors
in the code. The development of the partial cover tree and its accompanying algorithms
have not been easy, nor without its fair share of problems, hence errors are not out of the
question.
The algorithms that have been developed in this paper are theoretically in line with the
findings by [AL06] and the theoretical solution quality is also in line with the findings of
[Gor+20]. The difference is that we found m to be a factor (1+ϵ) greater than that found
by [Gor+20]. This may be because the ϵ used during the analysis has the size 0 < ϵ ≤1
hence this factor (1 + ϵ) is at most 2, hence it might be looked at as a constant factor.
This may be the case for small ϵ, but not if ϵ can take any positive non zero value. Then
again, the most interesting part of ϵ is when it is below 1 anyway.

Conclusion
We have fully covered the structure and algorithms that are used to create, maintain
an query both the full representation and partial representation cover tree data struc-
ture. It could immediately be used to solve the fully dynamic k-center problem with an
approximation factor of 8.
We saw that the extension of the cover tree to the cover forest is mush more interesting.
We found that we could solve the fully dynamic k-center problem with an approximation
factor of (2 + ϵ).
We found the theoretical run time of insertion and removal to be
O(c6 log(n) · ((1+ϵ)(ln(2)−ln(ϵ))
ϵ
)) where the last factor is the amount of cover trees in the
cover forest. Hence the space usage is also O(n · ((1+ϵ)(ln(2)−ln(ϵ))
ϵ
)).
We developed new techniques and algorithms that are required to maintain the partial
structure. We also saw that maintaining the structure require a significant amount of
work and is not immediately obvious how to do. In addition to this, we showed a couple
of errors in the previously done work, and showed why and how to mitigate them.
In the Experimental section, the single cover tree behaved as expected during removal,
exhibiting a trend of O(log(n)2), the insertion did however not behave as expected, and
followed the trend of O(log(n)2) similarly. When introducing the cover forest structure we
did however see great improvements to the solution quality for smaller ϵ, that is several
cover trees working together, we also saw a greatly increased query time. With regard to
insertion, removal and query time we saw an almost linear trend when m > 2 for point
counts greater than 100k. We also explored several different approaches for calculating α
and m, none of which were superior to the others but each behaving as expected.

Future work
Of course it would be prudent to implement the Remove() (algorithm 6) as described
in theorem 6.3.13 and reduce the run time of Remove() down to that of the originally
proposed algorithm in [AL06].
The implementation used in this paper were done using C#, as the Cover Tree / Forest are
intended for very large data sets, it would do no harm to implement them in a language
like C++ to gain the benefits of that. In the same train of thought, implementing parallel
computing to evaluate multiple trees in the forest at once, and executing on HPC clusters
along with larger data sets would be appropriate.
Finding the reasons for why both insert, remove and query exhibit linear trends for more
than two cover trees in the cover forest would also be of great interest. Then finding some
way of mitigating it to gain run times closer to the theoretical.
In the Remove() (algorithm 6) it would also be wise to save on the resources used. During
execution, many cover sets are created for the call stack.
They contain pointers, but
when the function is done, every reference to the cover sets are lost. As such the garbage
collector removes all the cover sets. If the cover sets could be kept in a list of sorts, and the
contents of the sets be overwritten when executing Remove() later it could save greatly
on the amount of garbage collection.
In the Insert() (algorithm 4) we have a similar problem with the cover sets, but unlike
Remove(), when we reach the end of Insert() and insert the point, we do not use the cover
sets any more. As such it would be possible to keep sets Qi, Q and Qi−1 in an iterative
fashion like the kClustering() process (algorithm 12).
